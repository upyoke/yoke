# Terms M–R

<!-- yoke:breadcrumbs -->
[Yoke](../index.md) > [Index](index.md) > M–R
<!-- /yoke:breadcrumbs -->

Draft definitions and links to the current documentation.

## Machine

A computer registered or configured to connect to Yoke and perform work. [Read more](../cli/machine-authorization.md).

## Machine approval

The human authorization step that allows a machine to connect. [Read more](../cli/machine-authorization.md).

## Machine configuration

Settings and connection choices stored for a particular machine. [Read more](../cli/machine-config.md).

## Manual setup

The optional path where a person runs the terminal setup wizard directly. [Read more](../start/terminal-onboarding.md).

## Master plan

The evolving strategy document describing how the project will reach its goals. [Read more](../strategy/index.md).

## Member

A person belonging to an organization, or an item included in a deployment run;
qualify the term. [Read more](../projects/actors-members-billing.md).

## Merge queue

The ordered process that checks and lands changes in an integration branch. [Read more](../github/merge-queue-landings.md).

## Migration

A controlled change to a database's schema or data. [Read more](../databases/migrations.md).

## Migration fleet

The set of live databases a release must account for and rehearse against. [Read more](../databases/migration-fleet.md).

## Mission

The strategy document stating the project's purpose; an exploratory mission is a
separate QA concept. [Read more](../strategy/index.md).

## Mode

May mean where Yoke runs, how setup is presented, or what a session is doing; use the
qualified name. [Read more](../start/modes.md).

## Model

An AI model used by an agent, or a declared database/architecture model; qualify the
term. [Read more](../functions/models.md).

## Model catalog

The versioned catalog of models used in execution-level configuration. [Read more](../functions/models.md).

## Onboarding

Helping a project adopt Yoke, connect its existing work and reach its first delivery. [Read more](../start/agent-setup.md).

## Organization

The shared identity and membership boundary for people using Yoke together. [Read more](../projects/actors-members-billing.md).

## Ouroboros

The learning process that turns observations and recurring problems into improvements. [Read more](../operations/ouroboros.md).

## Pack

Reusable project setup and guidance for a capability or stack. [Read more](../agents/rules/packs.md).

## Parked session

A session deliberately waiting, with a recorded reason, while retaining its work. [Read more](../sessions/index.md).

## Path claim

Recorded ownership of file paths used to coordinate overlapping work. [Read more](../sessions/model/path-claims.md).

## Persona

A named browser identity used for a role or account during QA. [Read more](../verification/browser-identities.md).

## Plan

May mean a strategy document, an implementation plan or a QA plan; these have
different owners and purposes. [Read more](../strategy/index.md).

## Post-deploy QA

Checks that prove the required behavior after deployment. [Read more](../verification/deployment-plan-execution.md).

## Project

A named body of work with its own goals, backlog, configuration and guidance. [Read more](../projects/index.md).

## Project installation

Adding or refreshing the Yoke guidance and harness configuration for a checkout. [Read more](../start/project-install.md).

## Project structure

The declared organization of a project's source, tests and other components. [Read more](../databases/model/projects.md).

## Provider

A service supplying a configured capability, such as model access or infrastructure. [Read more](../projects/capabilities.md).

## QA

Quality assurance: defining what must be checked, performing checks and evaluating the
evidence. [Read more](../verification/index.md).

## QA activity

The view of case outcomes, requirements, runs and supporting evidence. [Read more](../verification/index.md).

## QA artifact

A log, screenshot, trace or other supporting material attached to QA evidence. [Read more](../verification/model/qa.md).

## QA attachment

The binding that applies a plan or case to the work and gate it must check. [Read more](../verification/case-attachment.md).

## QA case

One defined check in a plan, using a method and its configuration. [Read more](../verification/case-attachment.md).

## QA kind

The purpose of a check, such as smoke testing or implementation review. [Read more](../verification/platform.md).

## QA method

The registered contract describing how a case performs and proves a check. [Read more](../verification/index.md).

## QA plan

A project-owned collection of ordered cases and their attachments. [Read more](../verification/index.md).

## QA requirement

A concrete obligation to provide qualifying evidence for a subject. [Read more](../verification/platform.md).

## QA run

One recorded attempt to satisfy a QA requirement. [Read more](../verification/model/qa.md).

## QA subject

The item, task or deployment run a requirement is about. [Read more](../verification/platform.md).

## QA verdict

The recorded judgment of a check's outcome, supported by its evidence. [Read more](../verification/requirement-state.md).

## Registered command

A project's declared test command bound to a QA scope and case. [Read more](../verification/index.md).

## Relay

The background service that supports session communication and supervision on a
machine. [Read more](../sessions/linux-relay.md).

## Release

A delivered version whose identity and required evidence are recorded. [Read more](../deployments/model/releases.md).

## Release authority

The rule and evidence source used to establish what version is deployed. [Read more](../deployments/model/releases.md).

## Requirement

Usually a QA requirement: an obligation that must be satisfied, not the attempt to
satisfy it. [Read more](../verification/platform.md).

## Restore

Recovering a universe from a backup into a chosen destination. [Read more](../start/install.md).

## Review

Inspection of work or evidence before accepting a result or allowing advancement. [Read more](../workflows/gates.md).

## Run

An execution record; distinguish QA run, deployment run and setup/onboarding run. [Read more](../verification/model/qa.md).

## Run member

An item admitted to a deployment run, with associated delivery and QA obligations. [Read more](../deployments/model/run-members.md).
