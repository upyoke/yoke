# Terms A–D

Draft definitions and links to the current documentation.

## Acceptance criteria

The conditions a change must meet to satisfy its intended outcome. [Read more](../items/index.md).

## Actor

An identity authorized to perform operations in a universe. [Read more](../projects/actors-members-billing.md).

## Agent

A coding assistant that uses Yoke to carry out work with you. [Read more](../agents/index.md).

## Agent mode

Setup conducted through questions your agent relays to you. [Read more](../start/agent-setup.md).

## Agent role

Instructions defining a worker's responsibility, such as implementation or review. [Read more](../agents/index.md).

## AGENTS.md

Repository instructions loaded by supported coding agents. [Read more](../agents/harness-discovery.md).

## API

The interface clients use to read and change Yoke state through registered operations. [Read more](../functions/index.md).

## Approval

A human decision required before an operation or deployment stage can proceed. [Read more](../deployments/model/flows.md).

## Architecture model

A project's declared structure and relationships, used to reason about change impact. [Read more](../agents/rules/architecture-model.md).

## Artifact

Stored supporting material, such as a screenshot, log or trace from QA. [Read more](../verification/model/qa.md).

## Attachment, QA

A binding that makes a QA case applicable to an item, task or deployment target. [Read more](../verification/case-attachment.md).

## Authentication

Proving which identity is connecting to Yoke. [Read more](../cli/machine-authorization.md).

## Authorization

The permissions that determine what an authenticated identity may do. [Read more](../projects/actors-members-billing.md).

## Backlog

The recorded work for a project, including work that is not ready to start. [Read more](../items/index.md).

## Backup

A saved universe export that can be used to restore its data. [Read more](../start/uninstall.md).

## Blitz

A workflow that carries out work defined by a linked strategy document. [Read more](../workflows/index.md).

## Blocked

Work that cannot proceed because a required condition or dependency is unmet. [Read more](../items/model/dependencies.md).

## Browser identity

A configured identity used to sign in during browser QA. [Read more](../verification/browser-identities.md).

## Browser QA

Checks performed through a browser against a specified target. [Read more](../verification/browser-targets.md).

## Browser scenario

The actions and assertions that describe a browser check. [Read more](../verification/browser-scenarios.md).

## Capability

A configured resource or integration a project can use, such as a provider or test
machine. [Read more](../projects/capabilities.md).

## Capacity

The available ability to launch or continue agent work within configured limits. [Read more](../agents/capacity-recovery.md).

## Case

Usually a QA case: one check in a QA plan. [Read more](../verification/case-attachment.md).

## Charge

The agent entry point for selecting and dispatching available work from the frontier. [Read more](../strategy/charge-dispatch.md).

## Claim

Recorded ownership of work, paths or steering scope that coordinates concurrent
activity. [Read more](../functions/claims.md).

## CLI

The yoke command-line interface, used by agents and available to people. [Read more](../cli/index.md).

## Command group

Related CLI commands under a shared prefix, with their own help. [Read more](../cli/help.md).

## Connection

A saved route from a machine to a Yoke universe. [Read more](../start/modes.md).

## Consumer proof

Evidence that a particular producer version works with a particular consumer version. [Read more](../verification/consumer-proof.md).

## Context packet

Focused operational guidance an agent requests when it needs it. [Read more](../cli/help.md).

## Control plane

The shared system that records and coordinates work, policy and delivery. [Read more](../index.md).

## Current plan

The strategy document describing the project's near-term focus. [Read more](../strategy/index.md).

## Dash

A workflow for direct execution from an agreed specification. [Read more](../workflows/index.md).

## Dashboard

The web interface for viewing and managing Yoke work and configuration. [Read more](../start/concepts.md).

## Database

A declared data store whose configuration and migrations Yoke can track. [Read more](../databases/index.md).

## Database model

The declaration used to describe and manage a database's migration behavior. [Read more](../databases/migration-model.md).

## Delivery

Getting a change to its intended destination with the required evidence. [Read more](../deployments/index.md).

## Dependency

A relationship that requires one piece of work or condition before another can
proceed. [Read more](../items/model/dependencies.md).

## Deployment

Putting a change into an environment through a defined delivery process. [Read more](../deployments/index.md).

## Deployment flow

A versioned sequence of stages that deployment runs execute. [Read more](../deployments/model/flows.md).

## Deployment run

One execution of a deployment flow against an environment. [Read more](../deployments/model/runs.md).

## Deployment stage

One step of a deployment flow, such as QA, approval or release work. [Read more](../deployments/model/flows.md).

## Deployment target

The destination against which deployment or deployed QA operates. [Read more](../deployments/model/flows.md).

## Doctor

Yoke's health checks and their findings and recovery guidance. [Read more](../operations/doctor.md).

## Done

The terminal outcome reached after a work item's required completion gates are
satisfied. [Read more](../workflows/lifecycle.md).
