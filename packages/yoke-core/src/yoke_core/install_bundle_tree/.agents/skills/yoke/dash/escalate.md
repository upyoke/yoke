# Dash — clarification or agreed conversion

## Ask and keep the Dash

A decision boundary needs operator meaning/authority: an unresolved
requirement, additional project needing a linked companion, missing
authorization, or irreconcilable requirement conflict.
State grounded findings, the precise question and what each answer changes.
Keep this item/lane, checkpoint and wait, then continue under the answer.
Do not draft an Issue, cancel or read its workflow projection for an ordinary
clarification. Size, planning, coordination and incremental work stay Dash.

## Convert only by agreement

Conversion requires an operator request, or explicit agreement to a concrete
need for parallel lanes/generated task graph. Never propose it for size.
Only then resolve the item's project and read
workflow.execution_instruction.resolve for Issue:

```text
yoke workflow execution-instruction resolve --workflow issue --project PROJECT --full
```

Apply instructions; present grounded findings, structural need, proposed
title/framing and that escalation cancels this Dash. Ask and wait.
No filing, cancellation or continued implementation while agreement is pending.
After explicit agreement, direct_workflow.dash.escalate is:

```text
yoke direct-workflow dash escalate ITEM --issue-title "<specific title>" --findings "<grounded outcome and remaining work>"
```

It idempotently links one absorbing Issue and cancels the Dash.
Stop execution after success; release a still-held claim if not already
released. Declined conversion follows the operator's actual continue/narrow/
park direction without filing.
