## Worktree Decomposition

Read before grouping tasks, after shared-file analysis and before lane plan.
Default independent multi-worktree fan-out; Conduct dispatches one Engineer per
active lane in parallel. Single lane requires actual structural blocker.

1. Partition tasks into maximal groups with satisfiable internal dependency order
   and disjoint combined edit scope. Attested coordination_only allows compatible
   additive settings/different-function overlap across otherwise independent lanes.
2. Find foundation: outputs consumed through live registry/data/migration/packet
   or imported verified module by all others. It lands first; consumers carry
   directional cross-lane activation dependencies.
3. In **Worktree Decomposition** name each lane/tasks/budget roots and structural
   justification. Single-lane choices cite linear live DAG, dependent same hunk
   or tiny epic<=3. Shared claim/convenience is insufficient. Same-hunk dependent
   source edits cannot become independent through coordination_only.
4. Branches: PREFIX-{N} or PREFIX-{N}-{short-kebab-primary-concern}. All same-lane
   tasks share worktree value; Conduct creates one tree per distinct value.
5. Each lane registers its own complete path claim when enabled; widening is
   per lane, never one epic-wide claim pretending to cover independent lanes.

Read effective budget/claim axes first; disabled budget uses execution edit
scope, disabled claims retain overlap evidence without registering claims.
Independent consumer groups can follow foundation in parallel; an integration
task follows required consumer merges. Do not split a genuine linear live DAG,
dependent same-hunk changes, or tiny work whose lane overhead exceeds savings.
